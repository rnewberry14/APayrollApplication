# How to Report Feedback

## What this page does

This article explains how testers can report issues, confusing screens, and feature feedback consistently.

## When to use it

Use it during or after manual testing.

## Before you begin

Open the testing templates in `docs/testing`.

## Step-by-step instructions

1. Open `docs/testing/TESTER-FEEDBACK-FORM.md` for general feedback.
2. Open `docs/testing/BUG-REPORT-TEMPLATE.md` for a specific error.
3. Open `docs/testing/FEATURE-FEEDBACK-TEMPLATE.md` for improvement ideas.
4. Add app version/build, browser, Windows version, page, steps, expected result, and actual result.
5. Attach screenshots only after removing sensitive information.
6. Add the issue to `docs/testing/TESTER-ISSUE-LOG.md` if maintaining a shared log.

## What to check

- Steps to reproduce are clear.
- Expected and actual results are included.
- Severity is selected.
- Screenshots do not contain sensitive data.

## Common messages or errors

- Not enough detail: add exact page, button, and sequence.
- Screenshot includes sensitive data: retake or redact it.

## What this page does not do

It does not send feedback automatically or transmit data from the app.

## Privacy/safety notes

Do not include real SSNs, bank account numbers, EINs, passwords, API keys, or live payroll data in feedback.
